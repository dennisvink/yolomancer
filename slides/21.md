# Chunking, Embeddings, Vector Storage

Retrieval starts before embeddings.

You need chunks that preserve meaning:

- file path
- heading or symbol
- content
- line range
- timestamp
- source type
- tags

Then create embeddings for semantic lookup.

---

S3 Vector buckets can store vector indexes close to S3 data.

For an agent, that suggests:

- store raw project memory in S3
- store document metadata in DynamoDB
- chunk `PLAN.md`, `LEARNINGS.md`, logs, and docs
- embed each chunk
- store vectors in S3 Vectors with stable chunk IDs
- query nearest neighbours before a turn
- use DynamoDB to map chunk IDs back to source documents

The model should not remember everything.

It should ask for the right context.
